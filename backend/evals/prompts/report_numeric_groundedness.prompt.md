# Report numeric groundedness evaluator

## Task

You are evaluating one **Event ROI Dashboard** report slide deck — a 7-slide
marketing analytics report generated by an LLM (Gemini) from real query
results returned by Databricks Genie (a natural-language-to-SQL tool against
event/pipeline warehouse tables: `rpt_event_performance` and related). The
report's own system prompt explicitly instructs the generating model to "be
precise with numbers — do not round excessively or fabricate data," because
this report drives real marketing spend and pipeline-attribution decisions.

You are NOT evaluating writing quality, tone, or slide formatting. You are
evaluating exactly one thing: **does every specific number the report states
(counts, dollar amounts, percentages, rates such as fPOI/attendance
rate/conversion rate) actually trace back to a value present in the Genie
query results it was given?** A fabricated, rounded-beyond-recognition, or
unsupported number is the single worst failure mode for a tool whose entire
purpose is trustworthy ROI reporting.

## What you are given

- `INPUT`: the original report request (event name and any additional
  context the user supplied).
- `CONTEXT`: the raw Genie query results the report was generated from —
  tables of columns/rows per analytics question, plus per-query status
  (`SUCCEEDED`/`FAILED`/`DEMO`). This is the ground truth. Numbers not
  derivable from this context (directly, or via a simple stated calculation
  like `Attendance Rate = Attended / Registered × 100`) are unsupported.
- `OUTPUT`: the full synthesized 7-slide report text being scored.

## Scoring criteria

Score on a 0.0–1.0 scale (numeric):

- **1.0 (fully grounded)**: every concrete number in OUTPUT either appears
  directly in CONTEXT, or is a simple, correctly-computed derived metric from
  numbers that appear in CONTEXT (e.g. attendance rate, cost per lead, fPOI —
  these are legitimate derived metrics this app is designed to compute).
- **0.5 (partially grounded)**: at least one number is unsupported by CONTEXT
  (not present, not a valid derivation, or the derivation is arithmetically
  wrong), but the majority of numeric claims are traceable, and the report
  correctly labels genuinely missing data as "[Data Not Available]" rather
  than inventing a placeholder number.
- **0.0 (fabricated / hallucinated)**: one or more headline numbers (the
  slide's primary KPI, e.g. Total Pipeline, Attendance Rate, ROI/fPOI) are
  unsupported by CONTEXT, or CONTEXT indicates the underlying queries failed
  (`FAILED`/`DEMO` status) yet OUTPUT states specific numbers anyway instead
  of noting the data gap.

Do not penalize the report for stating "[Data Not Available]" where CONTEXT
genuinely lacks the data — that is the *correct* behavior this evaluator
wants to reinforce, not a failure.
